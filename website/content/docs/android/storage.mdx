### KEncryptedTokenStore

`KTokenStore` backed by standard `SharedPreferences` with manual AES-GCM encryption.

Tokens are encrypted at rest using AES-256 GCM (key stored in Android Keystore).
Recommended for production use on Android 6.0+ (API 23).

This implementation replaces the deprecated EncryptedSharedPreferences
and uses standard platform APIs (Keystore, Cipher, SharedPreferences).


### KInMemoryTokenStore

In-memory `KTokenStore` implementation.

Tokens are never persisted — they are lost when the instance is discarded.
Intended for unit tests and mock environments where persistence is undesirable.

Usage:
```kotlin
// In tests
val store   = KInMemoryTokenStore()
val session = KSessionManager(store)

// Pre-seed a token for authenticated tests
val store = KInMemoryTokenStore(
    initialAccessToken  = "test-access-token",
    initialRefreshToken = "test-refresh-token",
```

### KSessionCookieStorage

A `CookiesStorage` implementation backed by `KSessionManager`.

Maps the session tokens to named cookies so Ktor sends them automatically
on every request. Cookie names are configurable to match your API's expectations.

This storage is restricted to specific hosts to prevent leaking session tokens
to unrelated domains (e.g. analytics or 3rd party CDNs).

### KTokenStore

Abstraction over token persistence.

Kindling provides three built-in implementations:
- `KSharedPrefsTokenStore`  — plain SharedPreferences (default, not encrypted)
- `KEncryptedTokenStore`    — EncryptedSharedPreferences (recommended for production)
- `KDataStoreTokenStore`    — Jetpack DataStore
- `KInMemoryTokenStore`     — in-memory only (tests / mock)

Implement this interface to plug in any other storage backend
(Room, SQLCipher, system Keychain, etc.).

All methods are `suspend` — implementations may perform I/O safely.

Usage with `KSessionManager`:
```kotlin
val session = KSessionManager(
    store = KEncryptedTokenStore(context)  // swap freely
)
```

```kotlin
interface KTokenStore
```

**Members**

- `suspend fun getAccessToken(): String?` — Returns the current access token, or `null` if none is stored.
- `suspend fun getRefreshToken(): String?` — Returns the current refresh token, or `null` if none is stored.
- `suspend fun saveTokens( accessToken: String?, refreshToken: String?)` — Persists both tokens.
- `suspend fun clear()` — Removes all stored tokens.
